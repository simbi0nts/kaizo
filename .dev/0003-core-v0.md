# Step 0003 — Core v0: interpreter, checker, run/check/test/build
Date: 2026-10-27
Status: done

## Goal
A working single-binary core (`kaizo`) that can run, check, test and package GPLM programs.

## Decisions
- **Tree-walking interpreter** in Go (`core/`, ~2.3k lines, stdlib only). Fast to build, enough
  for both test projects. Bytecode/native codegen is a later optimisation that won't change apps.
- **Syntax**: keyword blocks, no operators, calls only, `end` closes everything. Full reference:
  `core/LANGUAGE.md` (this is what an agent reads before writing GPLM).
- **Tail calls** are real (trampolined in `apply`), because loops are recursion.
- **Static checker v0** (`check.go`) rejects, with file:line:col + hint (and `--json`):
  unknown names (with "did you mean"), wrong arity, wrong/missing record fields,
  **non-exhaustive match** (pattern-matrix algorithm, prints a missing example like `Some(Down)`),
  **undeclared effects** (`io term time net`), redefining builtins/prelude.
  A full static type checker is deliberately postponed ("start small").
- **Prelude** (`Option`, `Result`, helpers) is GPLM source embedded in the binary.
- **Libraries**: `import x` → `libs/x/*.gp`, used qualified (`x.f`). Types/constructors global.
- **build** = copy of the core binary + JSON bundle of all sources + length + magic `KAIZOBND`.
  At start-up the binary checks its own tail; if a bundle is there it runs it.
  ("bytecode" in 0001 is replaced by sources for now: simpler, same user-visible result.)
- **Terminal**: raw mode keeps ISIG, so Ctrl+C works; the core restores the terminal on normal
  exit, runtime error and SIGINT/SIGTERM. Linux only for now (`term_linux.go`).

## What was done
`core/{lexer,ast,parser,interp,loader,check,builtins,term_linux,main}.go`, `core/prelude.gp`,
`core/selftest.gp` (8 tests), `core/LANGUAGE.md`, root `Makefile`.

## How to verify
```
make core && build/kaizo test core/selftest.gp      # 8 passed
```
Checker smoke test: a file with a missing match case, undeclared `println`, typo'd name,
wrong arity and bad record field yields 7 precise diagnostics (tried manually).

## Known gaps
No static types; effects through function values untracked; no local recursion in lambdas.
