# Step 0015 — 3D demo scene (software renderer, integer math, X11)
Date: 2026-10-27
Status: done (Linux/X11)

## Goal
Human: "Let's try to build 3d demo scene."

## Decisions
- No GPU path: talking OpenGL to X would mean implementing GLX; out of scope. A software renderer
  sends each frame as an image (X11 PutImage, ZPixmap BGRX, split into strips < 256 KiB) — added to
  `libs/x11` as `pixel` and `image`.
- GPLM has no floating point → **fixed-point**: 256-entry sine table scaled by 4096 (generated by
  tooling, not typed), integer sqrt, integer perspective divide.
- Rendering by **colour spans per row** instead of per pixel: the cost grows with rows and spans.
  Convex, regular solids → face normal = face centre − object centre; back-face culling from it;
  Lambert lighting; painter's algorithm across objects (sort by face depth).
- Background: sky gradient; infinite checkerboard floor computed analytically per row (tile edges
  where world x crosses multiples of the tile size), scrolling, with distance fog.

## Scene
Bobbing six-colour cube, an orbiting octahedron and two small satellite cubes, all spinning, over the
floor (screenshot `img/0015-demo3d.png`). q / Esc / closing the window quits.

## Results
- `apps/demo3d/main.gp`: ~280 lines of GPLM, 4 tests (trig, rotation, span overlay, frame size).
- Frame render time **4–5 ms** for 640x400 (native, reference counted); shown at ~24–30 fps
  (paced to 33 ms per frame); a 17 s run rendered 511 frames.
- `make gui` (tests/gui.sh, renamed from gui_snake.sh) now also checks the demo: window opens,
  frames are rendered, q closes it. `make test`: 11 suites pass.

## Observations
- Two one-line lambdas with an `if … end` body were missing the lambda's own `end`; the parser
  reported the exact column. Explicit closing keeps paying for itself.
- Fixed point everywhere is workable but noisy (`div(mul(a, b), 4096)`); a `Fix` library or
  float support would make graphics code shorter. Candidate for a later language step.
